# 贾鹏那期「无法区分说话人」根因分析与修复

> 仓库归档；总流程见 [hermes-bilibili-batch-ingest.md](hermes-bilibili-batch-ingest.md)；后续批量升级与 merge P0 见 [hermes-dialogue-transcript-upgrade-20260922.md](hermes-dialogue-transcript-upgrade-20260922.md)。

- 日期：2026-09-21
- 执行：Hermes（容器内 `/opt/data/.venv-diar`）
- 素材：B站 `BV18Neu68EYh`《95分钟！不用怀疑，具身智能正进入"洗牌元年"》｜韩成龙Jackie 对话至简动力贾鹏，时长 5570.8s（95′20″）
- 对照素材（成功案例）：`BV1qwhh6cECq` 十字路口对谈徐梦迪，4835.8s（80′36″）

## 一、现象

同一套脚本、同一套模型，两期素材结果差异极大：

| 素材 | 分块 | 聚类原始分布 | 少数派 | 结果 |
|---|---|---|---|---|
| 徐梦迪（十字路口） | 4063 | `[648, 3415]` | 16% | ✅ 问答归属逐句正确 |
| 贾鹏（韩成龙Jackie） | 3924 | `[3909, 15]` | **0.4%** | ❌ 全片并成 1 段，身份判反 |

## 二、已排除的假设（逐条实测否掉）

1. **模型/权重没加载对** —— 否。`load_state_dict` missing 0 / unexpected 0；用模型自带样例音频可正常出 embedding。
2. **短块污染聚类** —— 否（这条在徐梦迪期上确实成立过，已修）。本期统计被 `MIN_EMB(1.2s)` 过滤的块数 = **0**。
3. **VAD 把主持人短问句切碎了** —— 否。VAD 区间长度中位 1.98s（徐梦迪期 2.82s），`<0.3s` 区间 0 个，主持人问句没有系统性被丢。
4. **VAD 阈值异常** —— 否（但确实偏低）。贾鹏期自适应阈值 −36 ~ −37 dB，徐梦迪期 −29 ~ −31 dB；语音占比都是 83–84%，属正常范围。
5. **embedding 没有区分度** —— **否，embedding 是好的**。前 5 分钟单独聚类 k=2 得 `[281, 17]`、silhouette 0.54；全片相似度分布 中位 0.772 / 标准差 0.150，明显不是单峰。

> 结论：**特征没问题、VAD 没问题、模型没问题 —— 问题出在聚类算法本身。**

## 三、决定性实验

用**转写里能识别出的提问点**当 ground truth（正则 `[?？]|吗|呢|你怎么|你觉得|请介绍|想问`），在前 30 分钟（12 个提问点、1281 个块）上横向比较三种判别方法：

| 方法 | 主持人块占比 | **提问点命中率** |
|---|---|---|
| A 全局层次聚类（脚本原逻辑） | 11/1281 = 0.9% | **0/12 = 0%** |
| **B 阈值法 z=1.5** | 202/1281 = 15.8% | **10/12 = 83.3%** |
| **B 阈值法 z=2.0** | 165/1281 = 12.9% | **10/12 = 83.3%** |
| B 阈值法 z=2.5 | 55/1281 = 4.3% | 5/12 = 41.7% |
| B 阈值法 z=3.0 | 22/1281 = 1.7% | 3/12 = 25.0% |
| C 分段聚类（每 5 分钟） | 148/1281 = 11.6% | 6/12 = 50.0% |
| C 分段聚类（每 10 分钟） | 143/1281 = 11.2% | 6/12 = 50.0% |

提问点：`0, 36, 45, 257, 273, 1007, 1042, 1318, 1326, 1331, 1333, 1347`（秒）

## 四、根因

**`AgglomerativeClustering(metric="cosine", linkage="average")` 在极度类别不平衡时会把少数派整体吞掉。**

- 少数派占比 16%（徐梦迪期）→ 工作正常；
- 少数派真实占比 <1%（贾鹏期：主持人全片只问了 18 句 / 3201 段 = 0.6%）→ 少数类的块彼此不够接近，在自底向上的合并过程中被**逐个**并入多数类，最终只剩 11–15 个块，无法形成第二个簇。
- 随后「身份推测」拿到一个几乎单类的输入，只能把唯一的大簇判成主持人 → 整篇并成 1 段、身份判反，属于**二次伤害**。

这不是数据问题，是**算法选型问题**：全局层次聚类隐含假设「各类规模可比」。

## 五、修复

`/opt/data/scripts/diarize-media.py` 增加自适应回退（聚类退化时自动切换）：

```python
cnt = np.bincount(labels)
if k == 2 and len(cnt) > 1 and cnt.min() / len(labels) < 0.02:
    major = int(cnt.argmax())
    c = X[labels == major].mean(axis=0); c /= (np.linalg.norm(c) + 1e-9)
    sim = X @ c
    labels = (sim < np.median(sim) - 1.75 * sim.std()).astype(int)
```

即：以**多数类中心**为参照做单类异常检测，相似度显著偏低者判为少数派（主持人）。

`/opt/data/scripts/merge-diarization.py` 同时修正身份推测优先级：

- 原：规则1「最早开口者 = 主持人」优先
- 现：**规则2「发言量更少者 = 主持人」优先**（块粒度较粗时规则1 会误判 —— 贾鹏期开场块 0.04–5.27s 把主持人提问和嘉宾回答混在一起，导致把嘉宾判成主持人）
- 两规则一致时结果不变，因此对徐梦迪那期无影响

## 六、最终结果与残留

**全量重跑（修复后）**：`[3909, 15]` → 触发回退 → 阈值法 → `[3401, 523]`，主持人 504.4s / 嘉宾 3748.0s，占比方向正确。

**质量仍有上限，如实记录**：

| 版本 | 提问点命中 | 说明 |
|---|---|---|
| 修复前（全局聚类） | 0/18 = 0% | 全片并成 1 段 |
| 阈值法（纯音频） | 9/18 = 50% | 长回答有误标 |
| 阈值法 + 文本启发式 | 10/18 = 56% | 12/3201 段被纠正 |

人工抽查：**约半数段落归属可能有误**（例：`1:24 有请彭哥` 是主持人却被标成贾鹏；`1:25 大家好我是贾鹏` 是嘉宾却被标成主持人）。好消息是短问句+长回答的**逐句切分**做对了（开场 `0:00 主持人提问` / `0:01 贾鹏回答`，此前是混在一个 5 秒块里）。

**结论**：这期素材的**物理上限就低** —— 主持人占比 0.6%，且几乎全是无文本特征的短插话，音频 embedding 区分度不足以支撑高精度。已写入文章，但正文前加了「可靠性低，谨慎引用」说明。

**未解决项**：
1. 1.6 秒块粒度仍会把「主持人短问 + 嘉宾开口」混进同一块（靠转写段级分配缓解）。
2. 要做到逐句精确需要 change-point detection；当前环境装不了 pyannote（与 torchvision 版本冲突 + 模型 gated）。
3. 若后续接手：建议先统计主持人发言占比，**<2% 直接放弃 diarization**，把工时省下来。

## 七、给后续接手者的建议

1. **跑之前先判值不值得**：统计转写里含提问特征的段占比，<2% 说明是「嘉宾独白型」节目，diarization 收益极低。
2. **看少数派占比**：聚类结果里最少类 <2% 一律不可信（无论素材）。
3. **别用全局层次聚类处理长音频 + 极端不平衡**；阈值法（单类异常检测）在本场景实测 83% 命中，分段聚类只有 50%。
4. **身份推测以发言量为准**，别信「最早开口」——块粒度会骗人。
