## 2. ⚠️ 重要澄清：「严格交替」并不存在

任务曾要求「取消严格交替」。实测**该逻辑在脚本里根本不存在**。

### 2.1 复现证据

用 Danfei 期（509 段）复现 merge 的分配过程，与 diar 原始输出**逐段对齐**：

```
转写段 spk 分配: 0000000000000000000000000111111111111111
diar 原始对照:   0000000000000000000000000111111111111111   ← 完全一致
```

- 合并前：`merged` 由 `coalesce()`（相邻同说话人合并）生成 —— **相邻必然不同人**，这是合并的**定义**，不是强制交替。
- 所以「相邻换人率 = 100%」是合并后的必然结果，**不能作为强制交替的证据**；「硬交替数」指标弃用。
- diar 原始输出的交替率仅 **26%**（1906 段），本身完全正常。

### 2.2 真正的病灶：短段误标

| 抽查点 | 实际内容 | 时长 | 误标形态 |
|---|---|---|---|
| 胡渊鸣 1:14:50 | 「你还会觉得」 | 1.0s | 主持人的一句话被切成 3 段，中间段判成嘉宾 |
| 周晨 42:00 | 「会有这种潜在的后发优势吗」 | 3.0s | 主持人的提问被判成嘉宾 |
| 杨硕 1:02 | 「这里是WhynotTV podcast」 | 2.0s | 片头语被判成嘉宾 |

**根因**：diar 的块粒度约 3.3s，主持人 1–3 秒的短插话在**时间上落在嘉宾长块中间**，merge 按「重叠最大的 diar 段」分配 → 归给嘉宾。

## 3. 修复方案：`--min-seg` 短段吸收

### 3.1 规则

```
短于 min_seg（默认现为 3.5s，见文首 PC 决策）的段，
若被两个「同属另一说话人、且本身都不短于 min_seg」的段夹住
→ 归入该说话人（合并文本、扩展时间），然后迭代到稳定。
```

### 3.2 为什么必须加「两侧本身不能是短段」

第一版只判断「被同说话人夹住」，结果**比修复前更糟**：当某人一句话被连续切成三段（主-嘉-主）时，**中间与两侧时长对称**，会把真正的主持人发言吞进嘉宾碎片。

实例（胡渊鸣 1:14:48–1:14:58，实为主持人一整句）：
```
1:13:42 【胡渊鸣】 长段
1:14:48 【主持人】 那given这样的论断      (2.0s)
1:14:50 【胡渊鸣】 你还会觉得             (1.0s)  ← 真正的碎片
1:14:51 【主持人】 一个general的robotic…  (6.0s)
```
- 第一版：处理 1:14:48 时两侧都被判为嘉宾 → **误吞主持人**。
- 加约束后：一侧是 1.0s 短段 → **不吸收**，保守不改（正确）。

| 期 | 段数 | 短轮(<3s) | 抽查 |
|---|---|---|---|
| 胡渊鸣 | 371 → 295 | 59 → 37 | 1:14:50 保守不改 |

| 杨硕 | 145 → 109 | 28 → 15 | **1:02 ✅** |

**全批**：短轮 2495 → 922（**-63%**）。

## 5. 🔴 `patch-article-transcript.py` 的 `---` 定位 bug

**症状**：贾鹏期写回后，`## Transcript` **之前**被删 942 字（章节目录后半 +「转写与笔记说明」）。Transcript 正文完好 → **只校验正文会漏掉**。

| 版本 | 代码 | 为什么错 |
|---|---|---|
| 初版 | `head.rstrip().rfind("---")` | 表格分隔行 `\|---\|---\|` 也含 `---` |
| 二版 | 取最后一个独立 `---` 行 | 有些篇 head 尾部无终止 `---`，命中 **frontmatter 结束符**，整段提炼被切掉 |

**正确**：只认「**其后到 head 末尾只剩空白**」的独立 `---` 行（位置判断，不用 MULTILINE `$`）。

**教训**：写回类脚本校验必须 **head + body 双覆盖**。

## 7. 坑与解法（本轮）

| # | 坑 | 解法 |
|---|---|---|
| 1 | `pkill -f` 自杀 | `ps \| grep "[r]un-xxx"` 取 PID 再 kill |
| 2 | 只杀 bash 不杀 python | 杀完 `ps` 确认无残留 |
| 3 | `capture_output=True` 吞进度 | DEVNULL + stderr PIPE 或 tee |
| 4 | ThreadPool 杀父不停子 | checkpoint / 杀完确认 |
| 5 | 内存耗尽（2 diar+2 转写） | 重任务并行 ≤2–3 |
| 6 | diarize 线程过度订阅 | diarize 钉单线程；转写不要钉 |
| 7 | `Path.with_suffix` 覆盖原转写 | 输出路径字符串拼接 |
| 8 | `top` idle 假 | 读 cgroup `cpu.stat` |
| 9 | `---` 定位切 head | 位置判断「其后只剩空白」 |
| 10 | 写回只比正文 | head + body 双校验 |
| 11 | Syncthing 属主写不进 | 备份→删→重建 + chmod 644 |
| 12 | 短段吸收无「两侧非短」约束 | 第一版更糟；必须加约束 |
